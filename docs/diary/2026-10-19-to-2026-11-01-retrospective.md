## 3. Python Analytics source review

The export contains three modules:

```text
analytics/
├── user_analysis.py
├── post_analysis.py
└── charts.py
```

### 3.1 `analytics/user_analysis.py`

Source-confirmed functions:

- `get_users_dataframe(session)`;
- `count_users(df)`;
- `users_by_role(df)`.

The User DataFrame contains:

```text
id, name, email, role, full_name
```

`users_by_role()` maps null roles to `unknown` and returns an empty DataFrame with the expected columns when the input is empty.

**Code-review finding — unnecessary sensitive-column loading:** `get_users_dataframe()` calls `select(User)`. The compiled SQL selects all mapped User columns, including `password`, `is_active`, `created_at`, `updated_at`, and `last_login_at`. The DataFrame later omits those fields, so the password is not returned by the helper, but the ORM query still loads it into memory.

Recommended change: select only the five columns needed for the current analysis instead of selecting the full User entity.

The DataFrame also omits lifecycle fields. That is a current scope limitation for account-lifecycle analysis.

### 3.2 `analytics/post_analysis.py`

Source-confirmed functions:

- `get_posts_dataframe(session)`;
- `posts_per_user(df)`;
- `calculate_post_statistics(df)`;
- `merge_users_posts(users_df, posts_df)`;
- `top_users_by_posts(users_df, posts_df, limit=10)`;
- `posts_by_role(users_df, posts_df)`.

The current Post DataFrame contains:

```text
id, title, content, user_id
```

It does not retain Post lifecycle fields such as `status`, `created_at`, or `updated_at`.

#### Empty-data defect

`get_posts_dataframe()` returns `pd.DataFrame(data)` without specifying columns. When the database contains no Posts, `data` is empty and the returned DataFrame has no `user_id` column.

The downstream helpers then fail:

```text
posts_per_user(empty_df)             → KeyError: 'user_id'
calculate_post_statistics(empty_df)  → KeyError: 'user_id'
merge_users_posts(users_df, empty_df)→ KeyError: 'user_id'
```

These failures were reproduced with isolated DataFrame checks during this audit. They do not require a database connection.

Recommended change: construct the empty Post DataFrame with an explicit column list, and test all helpers with zero Posts.

#### Average-population definition

`calculate_post_statistics()` calculates:

```python
df["user_id"].value_counts().to_numpy()
```

The result contains only users who have at least one Post. Therefore:

```text
average_posts_per_user
```

currently means average Posts per *posting user*, not average Posts across all Users.

The W25 diary correctly distinguishes the two metrics for the synthetic dataset:

```text
2,250 / 600 users = 3.75 posts per user
2,250 / 480 posting users = 4.6875 posts per posting user
```

The code's key name should be renamed to `average_posts_per_posting_user`, or the function should accept the full User population and calculate both metrics explicitly.

`merge_users_posts()` uses a left join and fills missing counts with zero. That is the correct basis for retaining Users who have no Posts, provided the Post DataFrame has the expected `user_id` column.

`np.std()` uses NumPy's default population standard deviation (`ddof=0`). Reports should label that definition if the standard deviation is presented.

#### Limit validation

`plot_top_users_by_posts()` rejects `limit < 1`, but `top_users_by_posts()` itself does not. The reusable analysis helper should validate its own public input rather than relying on the chart wrapper.

### 3.3 `analytics/charts.py`

Source-confirmed chart helpers:

- `plot_users_by_role(df)`;
- `plot_age_distribution(df)`;
- `plot_top_users_by_posts(users_df, posts_df, limit=10)`.

The age chart requires an `age` column. The current User model does not define age, and the chart docstring says it is not used by the FastAPI Analytics endpoint. It should be treated as a generic helper requiring a separate data source, not as a currently available User-model metric.

## 8. Root cause: incomplete source export

`export_project.py` defines this allowlist:

```python
ALLOWED_EXTENSIONS = {
    ".py",
    ".md",
    ".txt",
    ".ini",
    ".yml",
    ".yaml",
    ".sh",
    ".dockerfile",
}
```

This excludes several source types needed to review the SQL and dashboard:

```text
.sql
.json
.js
.mjs
.ts
.tsx
.css
.scss
.html
```

Consequences:

1. SQL analytics files are omitted from the file inventory and file contents.
2. JSON KPI and monthly snapshots are omitted.
3. `package.json` and TypeScript configuration are omitted.
4. Next.js page/component source is omitted.
5. JavaScript/TypeScript synchronization scripts are omitted.

Therefore, `Total included files: 139` is the count of files accepted by the exporter, not necessarily the total number of files in the repository.

### Recommended exporter improvement

Extend the allowlist with the file types required for this project:

```python
ALLOWED_EXTENSIONS = {
    ".py", ".md", ".txt", ".ini",
    ".yml", ".yaml", ".sh", ".dockerfile",
    ".sql", ".json",
    ".js", ".mjs", ".ts", ".tsx",
    ".css", ".scss", ".html", ".toml",
}
```

Add generated/dependency/build directories to `EXCLUDED_DIRS`, such as `.next`, `.vercel`, `out`, `dist`, `build`, and `coverage`.

Exclude large lock/generated files where appropriate, for example `package-lock.json`, `pnpm-lock.yaml`, and `progress.generated.json`, while retaining `package.json` and the KPI snapshot JSON files.

After updating the exporter, regenerate `project_context.md` and verify that the project structure includes:

```text
sql/analytics/*.sql
mentor-web/package.json
mentor-web/scripts/*.mjs
mentor-web/src/**/*.tsx
mentor-web/src/data/analytics-kpi.snapshot.json
mentor-web/src/data/monthly-posts.snapshot.json
```
